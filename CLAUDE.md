# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm test                  # run all tests (vitest)
npm test -- parser.spec   # run test files matching a pattern
npm run build             # runs tests then builds with vite
npm run publish:dev       # build + publish with --tag dev
npm run publish:latest    # build + publish as latest
```

## Architecture

**`@bou-co/parsing`** is an isomorphic TypeScript library for declarative data parsing, validation, and transformation. The core concept is a **projection** — a plain object that describes how to map/transform input data into an output shape.

### Entry points (three separate build outputs)

| Import path                          | Source                      | Purpose                                                              |
| ------------------------------------ | --------------------------- | -------------------------------------------------------------------- |
| `@bou-co/parsing`                    | `src/index.ts`              | Core parser + all types                                              |
| `@bou-co/parsing/types`              | `src/types/index.ts`        | Tree-shakeable built-in type tokens, classes + `defineType`          |
| `@bou-co/parsing/types/*`            | `src/types/**/*.ts`         | Opt-in subsets (`format`, `data`, `content`, `all`) and single types |
| `@bou-co/parsing/react`              | `src/react/index.ts`        | `useParserValue` hook                                                |
| `@bou-co/parsing/templates/localize` | `src/templates/localize.ts` | Locale transformer                                                   |

### Core files

- **`src/parser.ts`** — `Parser` class and `initializeParser` / `resolveVariables` exports. Each `initializeParser` call constructs an isolated `Parser` engine instance holding its own global context and caches (`new Parser(config)` is the advanced equivalent); parsers stay bound to the engine that created them, including when nested inside parsers from another engine. `createParser` (instance arrow, safe to destructure) returns a `ParserFunction` (an async callable with `.extend`, `.withContext`, `.projection`, `.flat` properties — `.flat` is a lazily-created variant marked `_flat: true` whose parsed result is merged into the parent output like `@combine`). `initializeParser` returns `{ createParser, resolve, cacheResult, types }` where `types` is the built-in token set (`DefaultParserTypes`). `cacheResult(key, fn, extraData?, options?)` (instance arrow) wraps a value function so its result is cached through the global `storage` via `storeValue` under a variable-interpolated key (`'profile-{{data.uid}}'`); the returned `CacheResultValue` wrapper is a plain callable (no reserved brands, so projection dispatch and `resolveNode` invoke it with the active context) plus a lazy memoized thenable — awaiting or calling it without a context runs it once against a root context built by `createRootContext` (shared with `resolve`) whose `data` is `extraData`; `extraData` otherwise only overlays `context.data` for key interpolation, `options` merge into `context.cache` for the backend, and the wrapper carries a content-derived `toString` (`__cacheResult:key:fnHash...__`) for `toHash` stability. `resolve` (instance arrow) runs pattern resolution (variable interpolation by default) and global transformers on raw input without a projection — it walks the input recursively, applying transformers at **every** nesting level (unlike parse, which applies them per projection-key value), awaits promises, invokes plain function values with the node `ParserContext` and recurses on their results (branded functions — `_type` tokens, `_parser` parsers — pass through untouched), resolves patterns in strings, and passes other leaves through; no casting, `@`-directives, or before/after hooks. `ParserContext.resolve` (wired in both `resolve` and `createProjection`'s `contextBase`, backed by `resolveWithParentContext`) is the contextual variant that inherits the active context — merged variables, transformers, locale — with per-call instance-context overrides; the global `resolve` never inherits ambient context. Return type is the mapped `ResolvedValue<T>`; `ParserResolveFunction` in `parser-types.ts` has two sentinel-default overloads whose order is load-bearing: constrained `T extends ResolveInput` first (gives function values contextual typing), plain `T` second (interface-typed inputs lack implicit index signatures) — an explicit `R` type argument overrides the inferred `ResolvedValue` mapping on both (explicit type args make remaining params take defaults, detected via the `ResolveTypeUnset` sentinel). `ContextResolveFunction` (the type of `context.resolve`) adds an arity-0 overload that lazily resolves `context.value` (raw `data?.[key]`, set on per-key contexts and mirroring `data` in transformer/pipe contexts), memoized per context. Functions nested inside another function's return value get no contextual typing — annotate their context param with `ParserContext`.
- **`src/type-token.ts`** — The casting primitive: `TypeToken<Out = any>` is a class whose instances are function carriers (`createCarrier`: an arrow function with its prototype swapped to the class, own `name`/`length` deleted; the constructor returns it, clones/derivations create fresh carriers) so a token can be called with an options object (`types.string({ default, required, strict, loose })` → `configure` → clone; a type or a `ParserContext` as the argument throws a targeted error); call signatures live on a merged interface with polymorphic `this`, which is why `Out` defaults to `any` (a parameter position mentioning `Out` would otherwise break subclass → `TypeToken` assignability). It carries its cast (`cast(value, context?)`, overridable; `undefined` means "missing"), a content-derived lazy `id` (built-ins by family name; derived tokens `<parent>.<member>(<params hash>)#<source hash>`; `{default:…}`, `:strict`/`:loose`, `<item>` and `(options)` suffixes — never instance/counter-based, persistent caches depend on it), `toJSON`/`toString` → `__parserType:<id>__` for `toHash`, and the universal chain: `.default(v)` and `.required` (`this & ParserTypeDefaulted`), `.strict`/`.loose` (policy pinned in `_state.policy` — there is deliberately no `strict` boolean field), `.extend(fn)` (anonymous subclass whose `cast` refines `super.cast` — keeps the family), `.to(fn)` (base-family derivation) / `.to(token)` (composition: subclass of the target with this cast as pre-step). Own state lives in a hidden `_state`; clones are `Object.create(proto)` + state copy so subclass overrides survive; accessor results are memoised per instance (`transform`/`derive` protected helpers, keyed by member + params). `defineType(fn | Class | { name, extends, fn, accessors, methods, default, required, strict, loose }, options?)` — the class form (`definition.prototype instanceof TypeToken`) is the factory the built-ins use (`defineType(StringType)`), the object form builds an anonymous subclass of `extends`'s class (`installMembers` puts getters/methods on its prototype); overload order matters (bare cast function first so `(value) => …` keeps contextual typing); its typing relies on overloads without type-parameter defaults and `extends: E & TypeToken<Out>` as the direct inference site. `isTypeToken` is `instanceof` plus a structural fallback (`_type` + `cast`) for dual-package builds. Also home of `applyCast` (`isMissing` = undefined/null/`''` → default, or a `Missing required value` failure when `_state.required`; a cast result of `undefined` → same; failure → `handleFailure`: `onCastError` → `strict` throws → `loose`/`{ fallback }` option → default silently → `looseCasting` (`true`; `'undefined'` alias, `TODO(v4)`) → default + `console.warn` → throw), `ParserCastError`, `buildKeyPath`.
- **`src/types/`** — One file per type, spec beside it. Built-in families are classes with `static readonly family` (`string.ts` `StringType`, `number.ts`, `boolean.ts`, `date.ts`, `object.ts`, `array.ts` `ArrayType<Item>` whose `cast` runs items through `applyCast` with `{ key: index, index, parent }` contexts and whose `.of()` is memoised per item id, `any.ts`, `unknown.ts`) and the tier-1 catalogue (`text` — textarea tidying that keeps line breaks, plus `singleLine`/`characterCount`/`wordCount`/`lineCount`/`lines`/`paragraphs`/`readingTime()` backed by `countWords`/`countCharacters` in `internal.ts`; `email` — case kept as written, `normalized`/`href`/`local`/`domain`; `url` (`.base()` via `_state.options`); `slug` — documented ASCII pipeline: transliteration table → NFKD → strip `\p{M}` → lower → `-`; `color`; `tel` — value kept as written, `parseTel` shared by the cast and `normalized`/`href`/`extension`; `mime-type`, `json`, `unique` (a `notAPipe` factory), `one-of`, `pattern`). String-valued derivations return `StringType` via `.to(string)` so they chain (a composition onto a bare family root keeps the parent's name, so errors say `tel.href`, not `tel.href.to(string)`); array-valued ones (`split`, `lines`, `paragraphs`) use bare `.to(array)` because an item cast would report empty segments as missing. `namespace.ts` holds the frozen tier-1 `types` map (with the throwing `undefined` getter, `TODO(v4)`), `mergeTypes` (memoised by `(base, layer)` identity; accessor maps extend a family through `withAccessors`, tokens/factories replace with a warning when shadowing a built-in), the root accessor index (built from prototype descriptors without invoking getters; names declared by two families lose the root form — silent for built-in-only collisions like `length`, warned otherwise) and `resolveTypePipe` (explicit `pipes` win; `name[:params]` → token or literal factory; `name.member…` walks getters/methods with params on the last one, `strict`/`loose`/`default` are the only universal members reachable; root names map to their owning base token). `format.ts`/`data.ts`/`content.ts`/`all.ts` are the tier-2 barrels over the `format/`, `data/`, `content/` folders; `content/` is the only place that imports the optional peers (`sanitize-html`, `ultrahtml`, `marked`), lazily through `createLoader` so a missing package is an actionable error.
- **`src/parser-casting.ts`** — Thin re-export shim (`applyCast`, `TypeToken`, `types`, …) plus the v2 legacy-type-key migration catch (`assertNotLegacyTypeKey`, `TODO(v4)`). V3 ships transitional `TODO(v4)` migration catches for leftover V2 usage — grep `TODO(v4)` to remove them all in V4: `assertNotLegacyTypeKey` + the non-enumerable throwing `types.undefined` getter (`types/namespace.ts`), the `'undefined'` `looseCasting` alias (`type-token.ts`), the pipes-left-in-`variables` hint (`parser-expression.ts`), and the throwing `Parser` statics + full-context-as-2nd-argument catch (`parser.ts`); covered by `tests/migration-catches.spec.ts` and `tests/legacy-keys.spec.ts`. Parser functions hash by their projection (`__parser:` / `__parser-flat:` toString in `parser.ts`).
- **`src/parser-expression.ts`** — The expression grammar shared by every delimited pattern: `parseExpression` (quote-aware splitting on `||`, `|`, `:` — a `"…"` literal may contain any of them and `\"`; parsed expressions cached), `parseLiteral` (`"…"`, `-1.5`, `true/false/null/undefined`), `evaluateExpression` (per alternative: literal or `resolveCandidate` → pipes left to right → first defined result wins; an undefined candidate skips its pipes unless `pipeUndefined`; an undefined chain result continues), and `applyPipe`: explicit `context.pipes` first, then `resolveTypePipe` applied through `applyCast(..., { fallback: hasFallback })` ("fallback wins when written": a later `||` alternative turns a failed cast into undefined silently), then the legacy variables hint / not-found error.
- **`src/parser-patterns.ts`** — The pattern engine: `variablesPattern` (the shipped `{{ }}` default), `compilePatternRegistry` (merges defaults with the global `patterns` config — partial merge per existing key, `false` disables), the scanner (regex-clone based, longest-match-then-registration-order precedence, backslash escaping, per-string dedupe by unique match), the shared expression grammar (`||` fallbacks, quoted/numeric/boolean literals, `| pipe:params` looked up from `context.pipes` — dot paths are NOT split here, path semantics belong to each pattern's `resolve`; expressions require `delimiters: [start, end]` — the engine builds the match regex from them when `match` is absent, token patterns without delimiters force expressions off and throw if `expressions: true` is set), the index-based splicer (no `String.replace` `$`-hazard), fragment rescan with cycle guard (`ParserPatternCycleError`, depth cap + seen set), and the per-pattern cache layer (`'run'` = per root parse via a context symbol, `'none'`, `'storage'` = `context.store` with `pattern:<name>:<path>` keys). `parser.ts` seeds the compiled registry and run-cache Map onto root contexts under private symbols; spreads propagate them to every nested level. The variables pattern uses `cache: 'none'` because lookups are context-sensitive; its `resolve` keeps head-only `variableResolver` semantics and the engine-lifetime `cacheVariable` store, plus built-in terminal heads resolved live from the node context — `ctx`/`context` (the full `ParserContext`) and `data` (`context.data`) — checked after explicit variables but before `variableResolver` so they can never trigger external fetches.
- **`src/types/index.ts`** — The `@bou-co/parsing/types` entry: individual named exports of every built-in token and class plus `defineType`, for standalone type files; never pulls in the parser engine. Every non-spec file under `src/types/` is its own vite entry (glob in `vite.config.ts`) so `@bou-co/parsing/types/format/currency` resolves; `package.json` has `sideEffects: false` and top-level token instances are `/* @__PURE__ */`; `scripts/verify-bundle.mjs` (run by `npm run build`) asserts a named import tree-shakes and no subset pulls the content peers.
- **`src/parser-types.ts`** — All TypeScript types and the deep inference machinery that derives output types from projection schemas at compile time (`RealValue`, `_HandleProjectionObject`, `_HandleArray`, `_HandleIf`, `_HandleCombine`, `_HandleFlat`, `_HandleChildren`). `ParserType<Out>` / `ParserTypeWithDefault<Out>` / `ParserTypeToken` are compat aliases of `TypeToken`; `DefaultParserTypes` is `typeof types` from `types/namespace.ts`; `initializeParser` is overloaded so an object-form `types` config types the returned namespace (`RegisteredTypes`). `_HandleChildren`'s base map must stay homomorphic (`[K in keyof T]`) — mapping over a computed key set (e.g. `Exclude<keyof T, ...>`) forces eager evaluation and silently collapses doubly-nested parser output types to `{}`; extra key sets (defaulted-required fields) are layered on via `as`-remapped intersections instead.
- **`src/expandable-types.ts`** — Interfaces (`CommonContext`, `FunctionalContext`, `GlobalContext`, `InstanceContext`, `CreateContext`, `ParserCachingOptions`) intentionally left empty so downstream projects can augment them via declaration merging.
- **`src/parser-util.ts`** — Pure utilities: `typed`, `optional`, `condition`, `get`, `mergeObjects`, `filterNill`, `filterUndefinedEntries`, `asyncMapObject`. `get(path)` / `get(path, from)` are unchanged (the returned reader now hashes as `__get:<path>__`); `get(path, token)` and `get(path, from, token)` return a value function that yields the **raw** looked-up value and carries the token as a non-enumerable `_cast` brand (`GetValueFunction` / `GetValue` in `parser-types.ts`, hashing `__get:<path>:<token.id>[:<hash from>]__`) — the engine casts it after transformers and patterns, like a token at the key; the `from` form is also a thenable that casts against a root context (throws on failure). Overload order matters: token forms before `from` forms, since a token is a function.
- **`src/internal.ts`** — `getFromObject` for deep property access used internally.

### Projection key semantics (runtime dispatch in `parser.ts`)

Inside `createProjection`, each projection entry is dispatched by its value type:

| Value                                         | Behaviour                                                                                                                                                                                                                                                                                                                                              |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `types.string` / `types.email.domain` / etc.  | `TypeToken` instance (checked with `isTypeToken` **before** the function and object branches — tokens are objects now); value is **cast** as the final step, after transformers and variable resolution; missing values (`undefined`/`null`/`''`) skip casting (default applies, `required` fails); failures follow the two-flow policy in `applyCast` |
| `types.array` / `types.array.of(types.x)`     | Validates `Array.isArray`; `.of` form casts each item                                                                                                                                                                                                                                                                                                  |
| Legacy `'string'` / `'array<T>'` style keys   | Throw a runtime migration error                                                                                                                                                                                                                                                                                                                        |
| Literal non-type string/number/boolean        | Returned as a constant                                                                                                                                                                                                                                                                                                                                 |
| `Function` with `_parser: true`               | Nested `ParserFunction` — receives `data[key]` when it's a usable object/string; otherwise resolves projection-driven (see below)                                                                                                                                                                                                                      |
| `Function` with `_flat: true` (`parser.flat`) | Parses `data[key]` (projection-driven when missing), merges the resulting object into the parent output (key dropped, overrides regular keys like `@combine`); array results throw                                                                                                                                                                     |
| `Function` with `_cast` (`get(path, token)`)  | Called with `ParserContext` for the raw value; `_cast` becomes the key's cast token, so transformers → patterns → `applyCast` run on the result exactly like a token at the key (error path = the projection key). `resolveNode` honours it too (after resolving the result)                                                                           |
| `Function` (plain)                            | Called with `ParserContext` — `context.value` is the raw `data?.[key]`, zero-arg `context.resolve()` resolves it lazily (memoized per context); `'_inherit'` return means pass-through; returning a type token applies it as a cast; returning a parser applies it to `data[key]` (projection-driven when missing)                                     |
| `Promise`                                     | Awaited (typed as `Promise<unknown>` in `ParserProjectionValue`, e.g. `get(path, from)`)                                                                                                                                                                                                                                                               |
| `Object`                                      | Recursive nested projection — parses `data[key]` when it's an object / stringified object / full-string pattern (e.g. a variable) resolving to an object; otherwise resolves projection-driven                                                                                                                                                         |
| `'@array'` key                                | Signals the output should be an array                                                                                                                                                                                                                                                                                                                  |
| `'@if'` key                                   | Conditional fields: `[{ when(ctx), then }]` — appended to output                                                                                                                                                                                                                                                                                       |
| `'@combine*'` key                             | Merges the returned object into the output                                                                                                                                                                                                                                                                                                             |

**Projection-driven resolution** (`parseDataless` in `parser.ts`): the projection is the point of truth — when the input can't feed a nested projection (missing key, `null`, or a scalar), it still resolves against `{}` so constants, value functions, token defaults, and `@combine`/`@if` produce output; the incoming value stays reachable via `context.parent.value` (and `context.parent.data` holds the parent level's data object). Resolutions with zero own keys are dropped (`[key, undefined]`), preserving omit semantics and cascading through deep nesting. Array-shaped projections (`@array`, array literals, `asArray` — a lazy wrapper marked `_array` that hashes like its parser) keep the data-driven skip. Cycles terminate via `context.datalessPath` (projection refs accumulated only along data-less chains, including through `@if` then-parsers). The escape hatch for data-driven-only nesting is a value function that checks the data before returning the parser.

### Context hierarchy

Context is merged in this priority order (highest wins):

1. Instance context (passed per-call)
2. Schema context (passed to `createParser`)
3. Global context (set via `initializeParser`)

All three levels support `variables`, `pipes`, `types` (registrations: tokens/factories by name or accessor maps extending a family; merged into `context.types` next to `pipes` in `parse`, `createRootContext`, `resolveWithParentContext` and the caching proxy — set _after_ the context spreads, reusing the engine namespace by reference when nothing is layered), `cache`, `before`/`after` hooks, `looseCasting` (`boolean`: `true` = log and drop), and `onCastError` (called with the `ParserCastError` before the failure policy applies; replaces the default `console.warn`). Global context additionally supports `transformers`, `patterns`, `variableResolver`, and `storage` (for server-side caching). The global context can also be a (async) function, resolved lazily at first parse; only the object form's `types` reach the namespace returned by `initializeParser` (function-form registrations are pipe-visible only). `mergeObjects` (`parser-util.ts`) treats non-plain objects (tokens, `Date`) as atomic.

`before`/`after` hooks run per level (global → schema → instance, each once per parse level). Within the schema level, `.extend()` and `.withContext()` **compose** hooks instead of overwriting: `mergeParserContexts` in `parser.ts` chains them (base hook first, extension's second, receiving the base's returned context; identical references dedupe) while all other context keys keep plain `mergeObjects` merge semantics.

Value functions can cache individual async results via `context.store(key, fn, options?)` — get-or-compute through the global `storage`, independent of `cache.enabled`, with in-flight dedup per key. `context.storage` exposes the backend directly.

### Patterns & variable interpolation

A **pattern** (`ParserPattern`) detects a regex match inside string values and resolves it; transformers react to what a value _is_, patterns to text _inside_ it, and patterns run after transformers (transformer output is re-scanned). `{{variableName}}` interpolation is the built-in `variablesPattern`, resolved from `context.variables` — dot-path (`{{a.b.c}}`), OR fallback (`{{a || b}}`), chained pipes (`{{value | pipe:param | other}}`, explicit `context.pipes` first, then any type from `context.types` under its qualified (`date.iso`) or root (`upperCase`) name, with "fallback wins when written" failure semantics), spread (`{{...}}` returns the full variables object), built-in context heads (`{{data.*}}` = current level's `context.data`, `{{ctx.*}}`/`{{context.*}}` = the full live context; terminal fallbacks that user variables shadow and that never reach `variableResolver`), and lazy resolution via the `variableResolver` callback (called with the head segment only). The engine owns scan/dedupe/grammar/splice/rescan/parallelism; a pattern's `resolve` owns only path→value. A string consisting solely of one match returns the resolved value raw (objects survive); `\` escapes a match; rescan cycles throw `ParserPatternCycleError`. Configure via global `patterns` config: partial-merge an existing key to re-delimit (`patterns: { variables: { match: /\$\{([^}]+)\}/g } }`), `false` to disable, new keys to add coexisting syntaxes.

### Type inference

The TypeScript output type is derived entirely from the projection literal via the `RealValue` / `_HandleProjectionObject` chain in `parser-types.ts`. `ParserType<Out>` tokens carry their output type in a phantom symbol property (`PARSER_TYPE_OUTPUT`) that `RealValue` unwraps verbatim (custom object outputs keep required fields); functions map to their return type; nested objects recurse. `@if`, `@combine`, and `.flat` merge additional optional fields onto the output type; tokens with a `default` carry a second phantom (`PARSER_TYPE_DEFAULTED` via `ParserTypeWithDefault`) that makes their field non-optional. `ParserProjectionValue` deliberately includes only brand-only `ParserTypeLike` / `ParserFlatLike` members (no call signatures): a second callable in that union breaks contextual typing of plain value functions.

### Testing

Tests live in `src/tests/` as `*.spec.ts` files (type specs sit beside their type under `src/types/`), run with vitest (globals enabled — `vi`, `describe`, `it`, `expect` need no imports). Each spec typically calls `initializeParser` at the top to get a `createParser` bound to a test global context. Vitest does not type-check; `npm run build` runs the `tsc --noEmit` passes that do.
